# 2026-09-24

- 润色了 Project Sentinel（esc_project_monitor）项目方案描述，并写入 `README.md`：Hub-Agent 架构、无 Agent 优先采集、配置版本化拉取+热生效、插件化采集、企业微信告警、Go+Svelte+SQLite/VictoriaMetrics 技术选型、三阶段实施路线。
- 在当前目录实现了 Project Sentinel MVP（Go 1.22，仅依赖 modernc.org/sqlite 与 golang.org/x/sys）：
  - `internal/core`：Metric/Plugin 接口+全局注册表、HubConfig/AgentConfig/Rule/Silence、版本哈希（sha256 前16位）
  - `internal/scheduler`：通用调度器，对比任务 JSON 差异热生效（停止/重启/新增，不重启进程），Agent 与 Hub 探测共用
  - `internal/plugins`：sys(cpu/mem/disk/proc，按 OS 分文件 build tag，Windows 下 cpu 返回 ErrUnsupported、mem/disk/proc 已实现) 与 probe(http/tcp/ping)
  - `internal/hub`：store(SQLite WAL，metrics/alert_events/agent_configs/agent_state 四表)、alerter(阈值+持续时间+恢复+去重窗口+静默/维护窗口+企业微信 Markdown webhook)、server(配置下发 204/全量、report、push、Web API)、prober、内嵌 web/index.html 状态页
  - `internal/agent`：拉取配置(版本一致无变化)、缓存降级、攒批上报
  - `cmd/hub`、`cmd/agent`、`configs/hub.example.json`
  - 冒烟测试通过：配置版本化下发(204)、Push 上报、Hub 探测(http/tcp 成功)、Agent 采集上报(mem/disk/proc 正常)
  - 注意：本机沙箱的 rm/del 删除通道有缺陷（safe-delete 路径解析 bug），测试产物移入 data/（已 gitignore）。Linux/WSL 下 cpu/mem/proc 依赖 /proc 均可正常工作。
- 部署形态确认：**以 Agent 采集为主，且 Agent 仅支持 Linux/Ubuntu**（用户明确要求不需要 Windows Agent）：
  - 移除了 Windows 版 sys 插件（cpu_windows/mem_windows/proc_windows/diskstat_windows，删除通道异常故移入 data/pending-delete/）
  - sys 插件包全部加 `//go:build linux`，`cmd/agent/main.go` 加 linux 构建标签；Hub 不再 import sys 插件（仅 probe），Hub 保持跨平台可编译
  - 结果：Linux 全量编译通过；Windows 下 Hub 可编译（开发调试）、Agent 因 linux 约束被正确排除；依赖收敛为仅 modernc.org/sqlite（去掉了 golang.org/x/sys）
